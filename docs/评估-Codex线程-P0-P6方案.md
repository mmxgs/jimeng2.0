## 三、站得住的结论（已采纳）

1. **不要训练模型，先做"检索 + 组合"** —— 成本与平台依赖都更低，判断正确。
2. **三级能力划分**（检索套用 / 组件重组 / 原创视觉）—— 诚实，没有夸大"自动创造新风格"。
3. **风格原子拆分**（构图 / 光影 / 色彩 / 卡片 / 字体 / 密度 / 品类 / 失败模式）—— 字段设计合理。
4. **生命周期**（draft / generated / verified / stable / deprecated）—— 避免把草案当成熟资产。
5. **组合来源上限 3–4 个** + 互斥规则 —— 防止"随机拼贴"。
6. **第一版不做图像向量，用规则字段匹配** —— 务实，避免在脏数据上放大错误。
7. **P5/P6 明确暂缓**（视觉检索、LoRA/DreamBooth）—— 有优先级判断，不是什么都上。

## 四、缺口（评估没覆盖的）

| # | 缺口 | 后果 |
|---|---|---|
| G1 | **读图不可见的前置风险**：五项验收全靠多模态读图，而本机多次出现会话模型读不了图的情况 | P4 的"风格命中度"、P5 的"视觉相似度"都建立在能读图上，无降级路径 |
| G2 | **成本约束未纳入**：即梦 5.0+2k = **0 积分/张**，5.0Pro = 8 分 | 反而**低估**了可行性——多候选几乎免费，这是"生成 2–4 张再选优"能落地的前提，评估没算这笔账 |
| G3 | **新模板如何继承护栏没说**：只在边界段写了"不能学品牌/文字/人物" | 自由组合最容易失控的就是照抄，护栏没跟着继承会直接出事 |
| G4 | **差异度阈值与现状冲突**：它建议"总差异<3 分算同一套变体"，但 T5 的 A/B/C 开关本来就是同骨架变体 | 模板库已用"骨架冲突才独立成条"解决了，评估没意识到这条已存在 |
| G5 | **无回滚/上限思维**：skill 原有"修复 2 次不过就停手"，评估没有继承这个上限 | 新流程可能陷入无限重试 |
| G6 | **"固化进 SKILL.md"没给阈值** | SKILL.md 现已 20KB，无节制固化会继续膨胀 |

## 五、必须修正的三处（已在 v1.2.0 中修正）

| 项 | 评估原文 | 修正后 |
|---|---|---|
| **M1 一票否决** | 7 项 × 0–5 加权，≥28 verified / ≥32 stable | 补 5 个否决闸门：照抄画面 / 商品漂移 / 虚构品牌 / 虚构参数 / 水印未除，**命中即 failed，不看总分** |
| **M2 禁止填示例数字** | JSON 示例里直接写 `verified_runs: 3`、`success_score: 4.2` | 无数据一律 `null`；新增 `qc_status` 区分「已验 / 仅客观项 / 无 run 记录」；`verified_runs` 只填 `runs.md` 能追到的次数 |
| **M3 护栏继承** | 只说"不能学品牌/文字/人物" | 新草案**必须全套继承 6 条护栏句**，并在合成前过 `style-compatibility.json` |

另补 G1、G2 两条硬约束写进正文。
