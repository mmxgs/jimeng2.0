- 新的字体与画面关系
- 新的叙事方式
- 新的信息呈现形式

十几套通常还不足以稳定做到这一层。模型偶尔可以产出看似原创的结果，但不可控，也不一定适合电商转化。

## 判断“够不够”不能只看模板数量

比数量更重要的是模板差异度。

如果十几套模板其实都是：

```text
中央商品
+ 顶部标题
+ 底部三张卖点卡
```

只是颜色不同，那本质上可能只有一套风格。

反过来，如果十几套覆盖了：

- 中央 hero
- 左右分栏
- 三段式叙事
- 场景沉浸
- 参数爆炸图
- 产品平铺摄影
- POV 视角
- 模特体验
- 功能矩阵
- AR 界面
- 视频播放器叙事
- 留白极简主图

那十几套已经是一个不错的种子库。

可以给每两套模板计算差异度：

```text
构图差异        0～2分
色调差异        0～2分
镜头差异        0～2分
信息结构差异    0～2分
场景叙事差异    0～2分
```

如果两套模板总差异低于 3 分，可以认为它们只是同一模板的变体，不算两套独立风格。

## 建议你现在先做“半自动创新”

最合适的模式不是让 skill 每次都创造新风格，而是：

```text
识别产品
→ 判断产品类型和视觉需求
→ 检索3套相关模板
→ 生成3个新组合方案
→ 做兼容性检查
→ 用户选择其中一个
→ 编译专业提示词
→ 即梦生成
→ 验收
→ 成功后才加入正式模板库
```

例如 Agent 先返回：

```text
方案 A：T5-A1 + T6 光影 + C4 卡片
适合：突出产品高级感和三个核心功能
风险：暗色背景可能削弱透明材质

方案 B：T3 场景叙事 + T5-C2 变体矩阵
适合：展示产品在通勤、办公室和户外使用
风险：信息密度较高

方案 C：T11 单主体 Hero + T10 AR 微界面
适合：投流首图，视觉冲击强
风险：功能解释较弱
```

这样生成的新风格不是随机碰运气，而是有理由、有来源、有风险判断的设计方案。

## 给新风格设置“转正机制”

自动生成的新风格不要立即当成成熟模板。建议分为：

```text
draft       Agent 自动组合，尚未出图
generated   已经生成，但未验收
verified    至少一次完整验收通过
stable      跨两个以上产品或三次生成通过
deprecated  多次失败或不再使用
```

“正式模板”的最低标准可以设为：

- 至少生成3次；
- 至少2次构图落地；
- 至少跨2个产品验证；
- 商品结构没有严重漂移；
- 没有明显照抄参考图；
- 用户至少选择过一次；
- 失败模式已经记录。

## 对你当前情况的准确判断

你目前已经可以让 skill 自动生成：

> **新的风格组合方案和新模板草案。**

但暂时不应该宣称它能：

> **自主创造并直接交付稳定的新风格。**

最稳的定位是：

> 十几套风格作为种子库，Agent 根据产品识别结果，检索并组合风格组件，生成新模板草案；经过即梦出图、验收和用户选择后，成功方案才能进入正式学习库。

也就是说，**数量已经够启动，接下来缺的不是继续盲目增加模板，而是“拆解、组合、兼容性判断、评分和转正”这五个机制。**

把现在的流程：

升级为：

```text

→ 检索适配风格

→ 组合新模板草案

→ 编译即梦提示词
→ 生成多候选
→ 验收评分
→ 成功模板转正并入库
```

**优先级：最高，第一步推进**

目标：把现有十几套风格从“文档里的长描述”变成 Agent 可以检索和组合的数据。

## 1. 建立统一模板字段

建议新增：

```text
references/style-library.jsonl
```

每一条风格至少包含：

```json
{
  "style_id": "T5-A1-B2-C4",
  "status": "stable",
  "parent_style": "T5",
  "composition": "center_hero",
  "lighting": "dark_high_contrast",
  "palette": ["black", "blue", "violet"],
  "scene": "minimal_tech",
  "camera": "front_three_quarter",
  "information_layout": "three_feature_cards",
  "card_style": "rounded_glass",
  "headline_style": "large_bold_uppercase",
  "density": "medium",
  "compatible_categories": [
    "wearable",
    "consumer_electronics",
    "smart_device"
  ],
  "supported_ratios": ["1:1", "3:4"],
  "known_failures": [
    "small_text_gibberish"
  ],
  "verified_runs": 3,
  "success_score": 4.2
}
```

## 2. 把每套风格拆成“风格原子”

重点拆这些字段：

- 构图
- 主体位置
- 镜头角度
- 光影
- 色彩
- 背景
- 场景
- 卡片形式
- 文字层级
- 信息密度
- 画幅
- 适用品类
- 已知失败模式
- 禁止组合

例如，不要只写：

```text
T5：智能穿戴复合版式
```

而要拆成：

```text
composition: center_hero
lighting: bright_soft
card_style: icon_title_cards
scene: lifestyle_tech
```

## 3. 给模板增加生命周期

每套模板必须有状态：

```text
draft       草案，尚未生成
generated   已生成，但未完整验收
verified    至少一次验收通过
stable      多次生成、跨品类验证
deprecated  多次失败或已废弃
```

不要让 Agent 把所有模板都当成同等可靠。

## P0 完成标准

完成后，Agent 能回答：

```text
哪些模板适合这个产品？
哪些模板适合 1:1？
哪些模板容易出现小字乱码？
哪些模板已经跨品类验证？
哪些模板只是草案？
```

这一步完成之前，不建议直接做“自动创造新风格”。

# P1：先实现风格检索，不急着创新

**优先级：高，第二步推进**

目标：产品识别完成后，自动从现有库中找到最适合的风格。

## 1. 增加产品适配标签

产品识别结果增加：

```json
{
  "category": "portable_blender",
  "visual_traits": [
    "transparent_body",
    "white_base",
    "small_appliance",
    "portable"
  ],
  "selling_point_type": [
    "appearance",
    "convenience",
    "usage_scene"
  ],
  "recommended_visual_language": [
    "clean_home",
    "lifestyle",
    "premium_product_photo"
  ],
  "risk_factors": [
    "transparent_material",
    "small_structure"
  ]
}
```

## 2. 建立模板兼容性评分

每个候选模板按照以下维度评分：

```text
品类匹配度       30%
产品结构兼容度   25%
画幅匹配度       15%
卖点展示能力     15%
历史成功率       10%
文字风险         5%
```

得到类似结果：

```text
T5-A1-B1-C4：91分
T6-B2：84分
T10：66分
T8：42分，不推荐
```

## 3. 第一次只返回候选，不自动创造

Agent 先输出：

```text
推荐模板 1：T5-A1-B1-C4
原因：适合小家电，中央主体突出，功能卡清晰

推荐模板 2：T6-B2
原因：适合透明材质和高端质感

不推荐模板：T10
原因：AR 界面会抢占透明杯体的视觉主体
```

这一步的作用是验证检索逻辑是否合理，避免一开始就让组合器随机发挥。

## 建议新增文件

```text
scripts/style_retrieve.py
```

第一版不必使用图像向量，先用：

- 产品类别
- 视觉特征
- 画幅
- 卖点类型
- 模板标签
- 历史成功率

做规则和字段匹配即可。

## P1 完成标准

给定一个新产品，skill 能稳定输出：

- 3 个候选模板；
- 每个模板的匹配理由；
- 适用场景；
- 潜在失败风险；
- 推荐排序。

# P2：实现“受控组合新风格”

**优先级：高，第三步推进**

目标：让十几套已有风格能够自动组合出新模板草案。

## 1. 组合时限制来源数量

第一版不要让 Agent 同时混合五六套风格。

建议限制：

```text
1 个基础构图
+ 1 个光影体系
+ 1 个卡片/信息模块
+ 1 个场景语言
```

也就是最多来自 3–4 个模板。

例如：

```text
基础构图：T5-A1
光影：T6-B2
信息卡：T5-C4
场景：T3
```

## 2. 设定互斥规则

建议增加：

```text
references/style-compatibility.json
```

例如：

```json
{
  "rules": [
    {
      "if": ["composition:center_hero", "scene:multi_scene_narrative"],
      "result": "warning",
      "reason": "中央主体和多场景叙事可能争夺视觉中心"
    },
    {
      "if": ["density:high", "text_layout:many_small_cards"],
      "result": "reject",
      "reason": "小字乱码风险过高"
    },
    {
      "if": ["dark_background", "transparent_product"],
      "result": "warning",
      "reason": "透明材质边界可能不清晰"
    }
  ]
}
```

## 3. 输出“新模板草案”，不要直接当正式模板

新组合应有独立 ID：

```text
N001 = T5-A1 + T6-B2 + C4 + T3-scene
```

Agent 输出：

```text
新风格名称：暗色厨房科技广告风
来源：
- 构图来自 T5-A1
- 光影来自 T6-B2
- 卡片来自 C4
- 场景来自 T3

适用产品：
- 小家电
- 智能厨具
- 便携设备

主要风险：
- 透明材质边缘可能消失
- 小卡片副文可能乱码
```

## 建议新增文件

```text
scripts/template_compose.py
```

职责只做三件事：

1. 抽取风格组件；
2. 检查互斥关系；
3. 输出新模板草案。

不要让这个脚本直接生成最终 prompt。

## P2 完成标准

对同一个产品，skill 能生成：

- 2–3 个新风格组合；
- 每个组合有明确来源；
- 每个组合有适用场景；
- 每个组合有风险提示；
- 不会随机混入互相冲突的版式。

# P3：建立专业 Prompt 编译器

**优先级：高，第四步推进**

目标：把“产品事实”和“风格描述”严格分离，再编译成即梦可执行的专业提示词。

## Prompt 必须分成五层

```text
1. 产品事实
2. 产品结构保护
3. 风格和构图
4. 已确认卖点
5. 禁止项和验收约束
```

建议固定结构：

```text
## Product
只描述识别确认的产品事实。

## Composition
描述主体位置、画面比例、信息层级。

## Visual Style
描述色彩、光影、材质、镜头和背景。

## Selling Points
只写用户确认过的卖点。

## Constraints
禁止虚构品牌、参数、数字和参考图内容。
```

## 必须增加“事实白名单”

例如：

```json
{
  "confirmed_facts": [
    "transparent cup body",
    "white base",
    "portable form factor"
  ],
  "forbidden_claims": [
    "12-minute battery",
    "BPA-free",
    "99.99% sterilization"
  ]
}
```

这样即使 Agent 在组合新风格，也不能顺手创造产品卖点。

## 即梦提示词优化的使用规则

如果即梦内部还会继续优化 prompt，建议明确：

```text
允许：
- 优化语言表达
- 补充画面氛围词
- 调整描述顺序

禁止：
- 增加产品参数
- 增加品牌
- 增加未确认功能
- 改变产品结构
- 添加参考图文字
- 改变画幅和主体布局
```

## P3 完成标准

同一套新模板可以稳定生成：

- 产品结构不漂移；
- 不虚构参数；
- 不继承参考图品牌和文字；
- 构图基本落地；
- 风格差异能够被人工识别。

# P4：建立新风格验收与“转正”机制

**优先级：中高，第五步推进**

目标：避免 Agent 生成了很多看起来漂亮、实际不可复用的伪模板。

## 每次生成统一评分

建议沿用你现在的五项验收，再加两项：

```text
1. 拼字准确度
2. 虚构规格
3. 虚构品牌
4. 商品结构保真
5. 构图和信息层级
6. 风格命中度
7. 用户选择结果
```

每项 0–5 分。

可以定义：

```text
总分 ≥ 28：进入 verified
总分 ≥ 32 且跨两个产品：进入 stable
总分 22–27：保留为 generated
总分 < 22：标记失败，不进入学习库
```

## 新模板转正标准

建议至少满足：

- 生成 3 次；
- 其中 2 次构图基本落地；
- 至少跨 2 个产品验证；
- 商品结构没有严重漂移；
- 没有明显照抄参考图；
- 风格命中度平均 4 分以上；
- 用户至少选择过一次；
- 失败模式已经记录。

## 更新现有记录方式

你现在的 `references/runs.md` 可以继续保留人工总结，但另外增加结构化记录：

```text
references/run-index.jsonl
```

`runs.md` 负责读给人看，`run-index.jsonl` 负责给 Agent 检索。

---

# P5：再做图像级风格检索

**优先级：中，前面稳定后推进**

前四步可以先不使用复杂视觉模型。等模板字段和反馈数据稳定后，再增加：

```text
产品图视觉特征
+
模板示例图视觉特征
+
文字标签
+
历史成功率
```

用于更准确地判断：

- 两套模板视觉上是否相似；
- 新产品是否适合暗色、亮色或生活场景；
- 某套模板是否与透明、金属、玻璃材质兼容；
- 生成图和目标风格之间的相似度。

你现有的 `style_probe.py` 更偏向尺寸、亮度、色彩等量化检查，可以继续使用，但它不能单独判断完整的“风格相似度”。后续可以增加图像嵌入或多模态模型评分。

这一阶段不要过早推进，因为如果底层模板字段和评分标准还没稳定，视觉检索会把错误模式放大。

---

# P6：最后再考虑模型级微调

**优先级：低，暂时不要推进**

目前不建议先做：

- 自训练 LoRA；
- DreamBooth；
- 自建风格模型；
- 大规模自动爬取竞品图；
- 复杂向量数据库；
- 自动修改即梦模型参数。

原因是你的核心问题现在不是“模型不会画”，而是：

- 模板没有完全结构化；
- 风格组件还没有标准字段；
- 组合规则还不完整；
- 成功和失败反馈还没有完全机器可读；
- 新模板还没有成熟的转正标准。

先把 Agent 的“风格规划和 prompt 编译”做好，收益会更快、更稳定。

# 最终建议

你现在最先推进的不是“再收集更多风格”，也不是“直接让 Agent 自由创造”，而是下面三个动作：

### 第一优先级

把十几套现有风格结构化，形成真正的 `style-library`。

### 第二优先级

让 Agent 根据产品识别结果，从库里检索 3 个候选风格，并解释推荐理由。

### 第三优先级

让 Agent 从不超过 3 套风格中组合出 2–3 个新模板草案，再经过即梦生成和验收。

完成这三步后，你的 skill 就具备了真正的：

> **产品识别 → 风格检索 → 风格重组 → 新模板生成 → 结果反馈学习**

能力。

建议暂时把目标定为：

> **先实现“可解释、可复用的新风格组合”，而不是追求完全原创风格。**

这会是成功率最高、最容易验收，也最适合你当前即梦工作流的落地路线。
